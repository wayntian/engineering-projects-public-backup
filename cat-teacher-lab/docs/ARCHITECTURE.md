# 空间与交互结构

## 保留的层次

园区 → 建筑 → 楼层 → 位置/门/通路 → 房间 → 对象与操作。

已有节点ID、房间编号和边关系是基础。新增美术资产先映射到现有节点，不用图片倒推或重建建筑拓扑。楼梯只连接相邻楼层，不能跨层跳跃，也不能混用电梯井。

## 导航与观察分开

- 画面拖动：改变观察视角或有限图片内的位置。
- 选择目标：只选择当前节点的已有邻居。
- 前进与明确进入：达到条件后才提交节点变化。
- 返回：沿已提交的历史恢复。
- 冷启动：恢复有效检查点，不把未提交的接近状态当成已进入房间。

主线导览的目标是优先推荐正门方向，只提供建议，不自动行走、不建立新边，不替代手动选择。

## 两种图像模式

广场已有球形浏览模式。普通透视图使用有限边界的photo模式，不能把一张静态透视图无限重复包成球体。

本次四张入口图全部属于有限透视图。全景素材与相机方位校准仍是独立工作。

## 实验状态

实验配置、运行、停止、保存和记录复盘有自己的状态。关闭面板和停止实验不是同一动作。恢复时应保留已提交数据，明确显示中断，不把离线时间补造成采集结果。

当前电学演示是教学响应模型，未连接真实仪器，也不代表所展示电路的实测或完整电路求解，不能用作真实上电依据。

## 源码入口

- ConnectedBuilding.swift：结构节点、邻接与楼层关系。
- LightweightRoam.swift：观察、接近、进入、返回和检查点。
- PlazaPanorama.swift：原生容器与场景浏览器连接。
- ExperimentLoop.swift：虚拟实验界面与记录流程。
- ObjectGraph.swift、SceneEngine.swift：对象及场景交互参考。

这些文件依赖完整工程里的其他类型与资源，本轮只用于理解现有实现。
